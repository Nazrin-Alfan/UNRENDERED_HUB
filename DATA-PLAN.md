## v2.0 Blueprint Final (spec locked by the user 2026-11-07, verbatim in the edit brief)
- Dual-Layer stats replace points/live-time for the five Core Stats: Base Stat = 10 + floor(lifetime points / 50) + allocated level points (locked initial values STR 60 / AGI 26 / VIT 14 / INT 16 / PER 13); Momentum = points in the last 7 days / 7 against the same targets (STR 120, AGI 40, VIT 10, INT 20, PER 10). Verified baseline 7-day momentum (window ending 2026-11-07): STR 87,1 (610 pts), AGI 25,7 (180 pts), VIT 10,0 (70 pts), INT 0, PER 0 — supplied by the user in the brief; the baseline window contribution decays evenly as the window slides.
- INT/PER lifetime backfill locked: INT 320 pts, PER 160 pts (base stats 16/13) while their 7-day momentum honestly starts at 0.
- XP never decreases. Rank-Up Trials gate rank at level caps 9/19/29/39/49 with Overflow XP; trial conditions use the 5 Core Stats only (E→D: ≥3/5 at target + VIT mandatory + both weekly editorials; D→C: ≥4/5 + no penalty in 7 days; higher: 5/5). +3 Unallocated Stat Points per level from Level 9, forward-only, allocated via the [+] buttons (allocateStat action, persisted in the state store).
- Penalty Zone replaces XP cuts: empty day → next day's quest XP is held in the XP Vault; Penalty Quest (≥3 daily quests that day) flushes it; a failed penalty day burns the held XP. Empty day resets streak; a missed editorial slot on an active day instead triggers EDITORIAL BREACH (streak frozen + Make-Up Editorial debt, completable via the makeup quest or a later editorial post).
- Buffs: IRON WILL (VIT momentum 10,0 → +10% daily quest XP), SHARP INSIGHT (INT+PER at target → +25 XP editorial), FULL SYNC (5/5 at target → +30 XP per daily sync + Streak Supply Drop doubled from +50 to +100 XP at every 7-day streak milestone).
- FAME/IMPACT moved to World Influence: totals (15 follower, 2.879 reach) plus lifetime rates (6,8 and 130,9 per day at live time 22) with targets 10/150; excluded from trials.
- No schema migration needed: rank, heldXp, allocations, lastFullSyncDate, and lastSupplyStreak are new keys in the existing key/value `state` table; snapshots keep storing lifetime points.
- **Growth**: one quest_log row per quest completion (date + quest key + source auto/manual), one snapshot row per day, metric events appended for manual FAME/IMPACT/PER entries. No unbounded external fetching.
- **Ordering**: quests shown daily first (fixed spec order), then weekly; stat grid in spec order STR, AGI, VIT, INT, PER, FAME, IMPACT.
- **Time semantics**: all day boundaries in Asia/Jakarta (WIB); daily quests reset 00.00 WIB, weekly quests reset Monday 00.00 WIB; live time = calendar days from 2026-10-16 to today WIB.

## Draft News page (added 2026-11-10, user request)
- New third tab DRAFT in the Hub shell. Sources, all read host-side by the new privileged functions `fetchDraftPackages` / `readDraftImage` (same pattern as the dashboard's `fetchLiveSources`): `~/workspace/unrendered/news_pending.json` (entries with status `awaiting_user` = news already scanned and waiting for a decision; 229 at build time) joined with `~/workspace/unrendered/content-bank/INDEX.json` (title, genre, folder, files, caption; 226 of 229 have an INDEX entry, ids read from `id` or `content_id`) and the package files on disk under `content-bank/<folder>/`.
- Verified at build time: every one of the 226 indexed drafts has `caption.txt` on disk (161 via the `caption_file` field, the rest by the default name; 30 entries carry an inline `caption` instead); cover (4:5 variant preferred) and closing slide resolve for 201 via INDEX `files` and for the remaining 25 via a directory listing fallback (INDEX `files` is null there but cover + closing exist on disk). Drafts whose INDEX status is already `posted` are excluded, mirroring the dashboard queue guard.
- Images are never served at full PNG size (median cover ~0,9 MB, max ~2,4 MB): `readDraftImage` downscales with GraphicsMagick (`/usr/bin/gm convert -resize <w>x> -quality 84`) to a JPEG data URL, 560px for card thumbnails and 1080px for the cover + closing detail view. Folder/file names are validated as single path segments before any disk access.
- Decisions: the GASS UPLOAD / REVISI / TIDAK APPROVE buttons write only to the new `draft_decisions` table (migration 0004; content_id PK, decision enum gass/revisi/skip, free-text note for revisi, decided_at). Stage boundary set by the user: the upload + scheduling script that acts on these decisions comes later, so this page records decisions and nothing is uploaded, and `news_pending.json` / `approval_log.json` are NOT written by the Hub (the chat NEWS approval flow keeps owning them). Decided drafts stay visible under their filter chips with a decision badge so a decision can be changed (decideDraft upserts).

## GASS history (added 2026-11-10, user request: "buat histori GASS sungguhan")
- Problem found: the old GASS chip was only a filter over the still-waiting queue — `draft_decisions` was empty (0 rows; all approvals so far went through the chat NEWS widget) and any decided draft vanished from the view once it left the queue, so the tab always looked empty.
- Fix: migration 0005 adds the append-only `draft_decision_history` table (id, content_id, title snapshot, decision, note, source hub/chat, decided_at). `decideDraft` now batch-writes the current-decision upsert AND one history row per decision; history rows are never updated or deleted, so a changed decision keeps both entries.
- New action `getGassHistory` merges, newest first: (a) Hub gass rows from `draft_decision_history`, and (b) past chat approvals read host-side by the new privileged function `fetchApprovalLog` from `~/workspace/unrendered/approval_log.json` (entries whose decision starts with "gass"; verified at build time: 3 entries, all "gass upload" on 2026-11-07 — news-434, news-443, news-447 — each source-labeled "chat"). Each entry is enriched with live status: `posted` (join `dash_posted_log`, carries the post URL), `queued` (still in the fetchDraftPackages queue), or `gone`.
- Client: the GASS chip is relabeled HISTORI GASS and renders this merged history list (title, content id, decision time WIB, source, status badge, post link when aired) instead of filtering queue cards; the queue filters REVISI / TIDAK APPROVE are unchanged.

## Approved-draft poller for the no-card upload pipeline (added 2026-11-10, user request)
- Goal: the GASS UPLOAD button in the DRAFT tab gets a real upload path without a per-upload approval card: a scheduled cron polls this artifact via `artifact.invoke_action` every 5 minutes and hands the approved drafts to the instagram-cli upload script (the cron + script themselves live outside this artifact; the first run still shows ONE card where the user taps "Allowed for this scheduled task" for a permanent grant).
- Problem: `getDrafts` returns all ~229 queued drafts WITH full captions — far too heavy for a 5-minute poll.
- New action `getApprovedDrafts` (in `server/src/drafts.ts`): returns ONLY drafts whose LATEST decision in `draft_decisions` is still `gass`, as `{ contentId, folder, title, decidedAt }`, oldest approval first, with NO caption text. A decision later changed to revisi/skip drops the draft out (draft_decisions is the upserted latest-decision table). Drafts already aired are excluded two ways: they must still be in the approval queue (privileged `fetchDraftRefs` drops INDEX status `posted`) AND must not appear in `dash_posted_log`.
- New privileged function `fetchDraftRefs` (`server/src/privileged.ts`): metadata-only sibling of `fetchDraftPackages` — reads `news_pending.json` (awaiting_user) + INDEX.json title/folder, performs NO caption.txt reads and NO directory listings, so the poll is cheap. Folder is validated as a single safe path segment, same rule as the package resolver.
- Read-only by design: the action writes nothing, uploads nothing, and does not touch `news_pending.json` / `INDEX.json`. DRAFT tab behavior, decision buttons, and GASS history are unchanged.

## GASS duplicate fix (2026-11-10, user report)
- Bug: tapping GASS UPLOAD saved fine, but the draft stayed visible in the SEMUA tab (by design it lists the whole queue; MENUNGGU is the one that hides decided drafts), so the user tapped GASS again and `decideDraft` appended a second identical row to `draft_decision_history` — two entries for news-494 ~54s apart (confirmed in the captured data: history table had exactly 2 rows, both news-494 gass). No duplicate upload: `getApprovedDrafts` reads only the latest decision per draft and the post aired once.
- Fixes: (1) `decideDraft` is idempotent — repeating the same decision with the same note writes nothing and returns `alreadyRecorded: true`; a changed decision or changed revisi note is still recorded. (2) `getGassHistory` shows one entry per berita (latest gass decision per content id). (3) Migration 0006 deletes exact-duplicate history rows (same content_id + decision + note + source), keeping the earliest — this removes the existing news-494 duplicate in production data. (4) Client: the GASS button becomes "SUDAH DI-GASS ✓" and disables once recorded (TIDAK APPROVE likewise), repeat taps are guarded client-side too, and a clear "✓ Keputusan tersimpan" confirmation appears after saving. The intro copy now states that decided drafts stay in SEMUA with their badge and MENUNGGU shows only undecided ones.

## GASS history live status + read-back (2026-11-10, user report)
- Bug: a just-aired post (news-494, aired 16.02 WIB via the GASS pipeline) showed "TIDAK LAGI DI ANTREAN" in HISTORI GASS with no post link, and history rows had no way to open the package again. Two causes: (1) `getGassHistory` derived posted status only from `dash_posted_log`, a snapshot table refreshed solely by dashboard syncs, while INDEX.json already carried `status: "posted"`, `post_url`, and `posted_at` from the moment the upload script aired it (verified live for news-494); (2) history rows rendered only title/time/source/status, and `readDraftImage` refused anything no longer in `news_pending.json` (and `resolveDraftPackage` excludes INDEX-posted entries), so aired packages were unreadable from the Hub.
- Fixes: new privileged `fetchPostedIndex` reads INDEX.json posted entries host-side; `getGassHistory` merges them OVER `dash_posted_log` (live wins, snapshot is only a fallback), so posted status + post URL appear immediately. New privileged `fetchPackageById` + `resolvePackageFromIndexEntry` resolve a package (caption, cover, closing) straight from its INDEX entry with no queue membership and no posted exclusion — packages are never moved on disk after release, so this is safe. `readDraftImage` falls back to that INDEX resolution when the queue path yields nothing. New action `getHistoryPackage` feeds the client.
- Client: every HISTORI GASS row gets a BACA PAKET toggle that expands the caption plus the full cover and closing slides (via `getDraftImage`), with an honest not-found state if the folder is gone. The DRAFT intro copy now states that aired news leaves the queue and moves to HISTORI GASS where it stays readable. Aired posts are NOT returned to the queue (duplicate-upload risk).
